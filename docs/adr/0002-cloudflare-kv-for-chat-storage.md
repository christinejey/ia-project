# ADR-0002: Cloudflare KV для хранения истории чатов

## Статус
Принято

## Контекст
Данные чата (список диалогов и история сообщений) нужно хранить между запросами. Внутри Worker нет персистентного состояния — каждый запрос обрабатывается изолированно. Варианты:
- Внешняя база данных (PostgreSQL, MongoDB)
- Cloudflare D1 (SQLite на edge)
- Cloudflare KV (key-value хранилище)
- Cloudflare Durable Objects (stateful actors)

## Решение
Использовать **Cloudflare KV** с двумя типами ключей:

| Ключ | Значение | Описание |
|---|---|---|
| `chats` | `Chat[]` (JSON) | Единый список всех диалогов |
| `messages:{chatId}` | `Message[]` (JSON) | История сообщений конкретного чата |

Биндинг объявлен в `wrangler.toml`:
```toml
[[kv_namespaces]]
binding = "CHAT_KV"
id = "8367a27cd28c48818886034521c20ca4"
```

## Обоснование
- **Нет инфраструктуры** — KV namespace создаётся через Cloudflare API, не нужен отдельный сервер
- **Простая модель данных** — чат это список сообщений, реляционная база избыточна
- **Прямая интеграция** — KV доступен через `env.CHAT_KV` без SDK и сетевых запросов
- **Бесплатный тир** — 100 000 операций чтения и 1 000 операций записи в день

## Последствия
- KV eventual consistent — запись может быть не видна сразу в другом регионе (задержка до 60 секунд). Для чата это приемлемо.
- При росте истории одного чата весь массив `messages:{id}` читается и перезаписывается целиком — не масштабируется для очень длинных диалогов
- Нет транзакций — одновременные запросы могут перезаписать данные друг друга
