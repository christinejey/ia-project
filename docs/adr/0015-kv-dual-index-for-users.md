# ADR-0015: Двойной индекс KV_USERS для поиска по логину

## Статус
Принято

## Контекст

При аутентификации нужно найти пользователя по логину и проверить пароль.
Cloudflare KV поддерживает только `get(key)` — нет SQL-запросов, нет индексов, нет `WHERE login = ?`.

Варианты:
1. Хранить только `"user:{login}" → User` — быстрый поиск по логину, но нет поиска по ID (нужен для JWT)
2. Хранить только `"user:{id}" → User` + список `"users" → login[]` — поиск по логину требует итерации всего списка
3. Двойной индекс: `"user:{id}" → User` + `"login:{login}" → userId` — O(1) для обоих направлений

## Решение

**Двойной индекс** в KV_USERS:
```
"users"           → string[]   (список всех login-ов)
"user:{id}"       → User       (данные пользователя по UUID)
"login:{login}"   → string     (userId по логину — индекс)
```

При создании пользователя записываются все три ключа.
При удалении удаляются все три.
Аутентификация: `get("login:{login}") → id → get("user:{id}") → User`.

## Обоснование

- Аутентификация требует O(1) поиска по логину — без полного сканирования
- JWT содержит `sub: userId` — проверка токена требует O(1) поиска по ID
- Два KV `get` на запрос аутентификации — приемлемо (~1ms каждый)
- Список `"users"` используется только для admin-listing и `hasUsers()` — не является критическим путём

## Последствия

- Изменение логина пользователя требует обновления трёх ключей атомарно (KV не поддерживает транзакции — принято как ограничение: смена логина не поддерживается)
- При ошибке записи возможна рассинхронизация индексов — принято как редкий edge case
- `deleteUser` удаляет `login:{login}` и `user:{id}` и обновляет список `users` — три операции
