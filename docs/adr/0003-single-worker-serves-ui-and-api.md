# ADR-0003: Один Worker обслуживает и UI, и API

## Статус
Принято

## Контекст
Приложение состоит из двух частей: браузерный интерфейс (HTML/CSS/JS) и REST API (`/api/chats/*`). Варианты размещения:
- Отдельный хостинг для фронтенда (Cloudflare Pages, Vercel) + отдельный Worker для API
- Всё в одном Worker: HTML отдаётся как строка, API обрабатывается тем же кодом
## Решение
**Весь интерфейс встроен в Worker** как шаблонная строка `const HTML = \`...\`` в конце файла `src/index.ts`.

Маршрутизация реализована вручную:
```typescript
if (p === '/' && m === 'GET') {
  return new Response(HTML, { headers: { 'Content-Type': 'text/html;charset=utf-8' } });
}
```

## Обоснование
- **Один деплой** — нет синхронизации версий между фронтендом и бэкендом
- **Нет CORS** — UI и API на одном домене, все запросы same-origin
- **Простота** — не нужен отдельный бандлер (Vite, webpack) для фронтенда
- **На данном этапе** интерфейс статичен и не требует SPA-фреймворка

## Последствия
- При росте UI файл `index.ts` станет большим — в будущем стоит перейти на Cloudflare Pages Assets
- Нет hot-reload для фронтенда при разработке — `wrangler dev` перезапускает весь Worker
- Весь HTML хранится как строка в JS-бандле, что увеличивает его размер
