# ADR-0007: Три специализированных Worker вместо одного

## Статус
Принято (заменяет ADR-0003 на уровне системы)

## Контекст

Прототип `userchat-worker` совмещал UI, API и бизнес-логику в одном Worker.
При добавлении AI-агента и панели администрирования возникли конфликты:
- AI-вызовы занимают до 30 сек — недопустимо в HTTP-контексте пользователя
- Admin-функции требуют другой модели авторизации (role=admin)
- Queue consumer не может быть совмещён с HTTP-handler в одном деплое без усложнения кода

Варианты:
1. Один Worker с routing по prefix (текущее состояние прототипа)
2. Три независимых Worker с разными bindings и зонами ответственности

## Решение

Разделить систему на три независимых Worker:
- `webchat-worker` — пользовательский UI + API (HTTP)
- `agent-worker` — Queue consumer + Workers AI (без HTTP endpoint)
- `admin-worker` — панель администрирования (HTTP, только role=admin)

## Обоснование

- AI-инференс (~5–30 сек) выносится в отдельный изолированный процесс через Queue — не блокирует HTTP-ответ пользователю
- Каждый Worker имеет минимальный набор KV bindings — принцип least privilege
- Независимый деплой: изменение системного промпта не требует редеплоя webchat
- Cloudflare Workers позволяет деплоить неограниченное число Workers на одном аккаунте

## Последствия

- Три отдельных `wrangler.toml`, три CI/CD job-а
- Нужен общий модуль `@ia/shared` для переиспользования auth-кода (см. ADR-0012)
- `agent-worker` не имеет публичного URL — это намеренное ограничение
