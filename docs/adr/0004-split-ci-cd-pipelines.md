# ADR-0004: Разделение CI и CD на отдельные pipeline-ы

## Статус
Принято

## Контекст
Изначально все шаги (проверки + деплой) были в одном workflow `deploy.yml`. Это создавало несколько проблем:
- Деплой мог запуститься даже при частичном падении проверок
- Невозможно запустить CI отдельно для Pull Request без деплоя
- Сложно читать и поддерживать один большой файл

## Решение
Два отдельных файла:

**`.github/workflows/ci.yml`** — запускается на `push` и `pull_request` в `main`:
- Lint (ESLint)
- Dependency Scan (npm audit)
- Secret Scan (Gitleaks)
- Static Analysis (tsc --noEmit)

Все 4 job-а выполняются **параллельно**.

**`.github/workflows/deploy.yml`** — запускается только через `workflow_run`:
```yaml
on:
  workflow_run:
    workflows: ["CI"]
    types: [completed]
    branches: [main]

jobs:
  deploy:
    if: ${{ github.event.workflow_run.conclusion == 'success' }}
```

## Обоснование
- **Гарантия порядка** — деплой физически невозможен без прохождения CI
- **Параллельность** — 4 проверки идут одновременно, CI быстрее
- **CI на PR** — проверки запускаются на pull_request, деплой — нет
- **Связь по имени** — `workflows: ["CI"]` привязывается к полю `name: CI` в ci.yml

## Последствия
- Связка CI → CD держится на совпадении строки `"CI"` — переименование сломает цепочку
- Деплой срабатывает на любой успешный CI, включая те, что запущены не из `main` (защищено фильтром `branches: [main]`)
- Общее время доставки кода в продакшн увеличилось примерно на 1–2 минуты из-за ожидания завершения CI перед запуском CD
