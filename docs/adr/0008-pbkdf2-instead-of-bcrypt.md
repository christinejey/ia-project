# ADR-0008: PBKDF2 через Web Crypto API вместо bcrypt

## Статус
Принято

## Контекст

Для хранения паролей пользователей нужна криптографически стойкая функция хэширования.
Bcrypt — стандартный выбор для Node.js-приложений.

Проблема: Cloudflare Workers выполняются в V8 isolate без Node.js runtime.
Bcrypt требует нативных аддонов (`node-bcrypt`) или Node.js-специфичного API — оба варианта недоступны в Workers.

Варианты:
1. `bcrypt` / `bcryptjs` — несовместимы с Workers runtime
2. `argon2` — требует WebAssembly, дополнительная зависимость
3. PBKDF2 через `crypto.subtle` (Web Crypto API) — доступен нативно в Workers

## Решение

Использовать **PBKDF2 через `crypto.subtle`** (стандарт Web Crypto API):
- Алгоритм: PBKDF2 + SHA-256
- Итерации: 100 000
- Длина ключа: 256 бит
- Формат хранения: `"saltHex:hashHex"` (16-байтная соль + 32-байтный хэш)

Реализовано в `workers/shared/src/auth/password.ts`.

## Обоснование

- Web Crypto API доступен в любом Workers runtime без дополнительных зависимостей
- 100 000 итераций PBKDF2-SHA256 обеспечивают вычислительную стоимость, сопоставимую с bcrypt cost=10
- Нет внешних npm-зависимостей → меньше bundle size, нет supply-chain рисков
- PBKDF2 является NIST-рекомендованным стандартом (SP 800-132)

## Последствия

- Нельзя перенести существующие bcrypt-хэши без сброса паролей
- Параметры (итерации, длина) зашиты в `password.ts` — для изменения нужен редеплой
- Argon2 был бы предпочтительнее по устойчивости к GPU-атакам, но добавляет WASM-зависимость
