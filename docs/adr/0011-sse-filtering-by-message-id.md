# ADR-0011: Фильтрация SSE-ответа по ID сообщения вместо timestamp

## Статус
Принято

## Контекст

SSE handler (см. ADR-0010) должен найти ответ агента, который появился **после** конкретного сообщения пользователя.
Интуитивный подход: сравнивать `message.timestamp > userMsg.timestamp`.

Проблема: в Cloudflare Workers `Date.now()` **заморожен** на момент начала инвокации — это не wall-clock время.
- `webchat-worker` записывает user-сообщение с `timestamp = T1` (время своей инвокации)
- `agent-worker` записывает ответ с `timestamp = T2` (время своей инвокации)
- Поскольку инвокации независимы, `T2` может быть меньше, равно или больше `T1` непредсказуемо
- Фильтр `timestamp > T1` может пропустить ответ агента → клиент никогда не получает сообщение

Дополнительная проблема: KV не атомарен — при одновременных запросах порядок записей не гарантирован.

Варианты:
1. Фильтрация по timestamp — ненадёжна из-за заморозки `Date.now()`
2. Фильтрация по порядковому номеру — требует атомарного счётчика (нет в KV)
3. Фильтрация по ID (UUID) — позиционный поиск по массиву сообщений

## Решение

Клиент передаёт `afterId` — UUID user-сообщения, возвращённый сервером при POST:

```
afterIdx = messages.findIndex(m => m.id === afterId)
fresh    = messages.slice(afterIdx + 1).filter(m => m.role === 'assistant')
```

Поиск позиционный: найти user-сообщение по UUID → взять все assistant-сообщения после него.
Timestamp не используется для фильтрации — только для отображения в UI.

## Обоснование

- UUID генерируется сервером (`crypto.randomUUID()`) и уникален независимо от времени
- Позиционный поиск в массиве не зависит от состояния часов
- Решение устойчиво к любому clock skew между инвокациями Workers
- Простота: один параметр в query string, одна операция findIndex

## Последствия

- Клиент обязан сохранить `userMsg.id` из ответа POST и передать его в SSE-запрос
- Если user-сообщение не найдено по ID (гонка записи) — `afterIdx = -1`, возвращается пустой массив; SSE polling повторится на следующей итерации
- timestamp в Message остаётся для сортировки и отображения, но не для фильтрации
